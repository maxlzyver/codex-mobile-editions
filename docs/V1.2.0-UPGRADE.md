# V1.2 自动更新与旧版安装

V1.2.0 在 V1.1.0 发布源码上继续开发。Windows 11、Windows 10、macOS 保持各自独立更新目录和平台身份。

## 安装 V1.2

首次使用请下载对应平台的完整 ZIP，完整解压后启动。已有版本无法更新时，也可将完整 V1.2 包解压到新文件夹使用；电脑项目和官方 Codex 聊天仍在原位置，新安装需重新配对手机。不要用 GitHub 自动生成的 Source code ZIP 首次安装。

Windows 旧安装器存在助手启动后过早退出的问题，单纯提高 GitHub 版本号不能修复已安装的旧程序。本次验收重点为 V1.2 本身及后续自动升级，不要求早于 V1.1 的版本必须自动直升。

需要在原目录保留配对和设置升级的旧版用户，可使用发行页的可选更新修复包：

1. 完成任务，退出**移动助手**；无需退出官方 Codex。
2. 将修复包解压到独立目录，双击 Windows 的 `Repair-Update.cmd` 或 Mac 的 `Repair-Update.command`，选择旧移动助手目录。
3. 工具核对版本、平台、进程和文件校验值，备份旧安装器后修复更新入口，重启助手并请求更新。任务忙碌时仍需等待，不绕过任务检查。
4. 真正安装完成并重启后，版本才会显示为目标新版（本次为 V1.2.0）。修复工具不会只修改旧程序版本号。

## 让 V1.2 自动升级

电脑管理端打开“设置 → 更新与关于”，开启“自动更新”。默认仍为关闭；手机可以查看状态和版本说明，开关由电脑管理端管理。

开启后，程序自动检查 GitHub 的对应平台目录，固定提交并核对文件，等待任务和审批空闲后安装并重启。原有手机配对、电脑端设置和已上传附件保存在 `.runtime`，更新时保留；已安装运行组件及电脑项目也会保留。外观设置保存在各浏览器中；互联网临时连接地址可能因重启而改变。

关闭自动更新时，仍会在启动时及后台定期检查新版并显示说明和提醒，但不自动安装。“下次更新前不再提示”只忽略当前可用版本，不会隐藏更高版本，也不会关闭自动更新。

## 验证方法

使用隔离副本和模拟的下一版本进行端到端自动更新：预存自动更新设置，运行任务时不得安装，任务空闲后无需点击检查或安装即可完成下载、校验、旧服务退出、程序替换及新服务启动，并核对配置与数据哨兵。模拟未来版本只用于测试，不对外发布。

Windows 10 启动器有系统版本限制；Windows 11 主机上的测试副本只放宽该检查，其他启动逻辑保留，不能据此宣称完成 Windows 10 实机验收。macOS 的原生进程和更新流程由 Apple 芯片及 Intel 的 GitHub 运行器分别验证。具体结果以本次发行页及 Actions 为准。
